# REST API v1

API дополняет существующие маршруты и tRPC. Базовый путь: `/api/v1`.
Данные поступают из базы текущего экземпляра (УРТК или РГСУ).

## Доступ

Администратор открывает **API-токены** (`/lk/api-tokens`) и задаёт название.
Полный токен показывается только после выпуска. Сохраните его перед закрытием.
В базе хранится SHA-256 токена. Токен содержит 256 случайных бит.
Передавайте его через HTTPS в заголовке `Authorization: Bearer <token>`.
Передача токена в URL не поддерживается. Отзыв необратим; выпустите новый токен для замены.
Токены действуют до отзыва. Любой токен читает данные.

### Права на запись

При выпуске администратор отмечает права (поле `scopes`, `src/lib/api-scopes.ts`):

| Право | Что разрешает |
| --- | --- |
| `schedule:write` | Добавление, изменение и удаление пар, чтение скрытых пар |
| `teachers:write` | Добавление, переименование и удаление преподавателей |
| `groups:write` | Добавление, переименование и удаление групп |

Права нельзя изменить после выпуска: выпустите новый токен и отзовите старый.
Токены, выпущенные до появления прав, получили пустой список и остаются только для чтения.
Без нужного права запись возвращает 403 `FORBIDDEN`.

### Инструкция для агента

На странице API-токенов есть кнопки «Инструкция для агента» и «Скопировать инструкцию».
После выпуска токена доступна «Скопировать инструкцию с токеном» — текст уже содержит адрес сайта, токен и его права.
Текст инструкции строится в `src/lib/api-agent-instructions.ts`; это основное описание ручек записи.

## Маршруты

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/v1/groups` | Группы: `id`, `title` |
| GET | `/api/v1/teachers` | Преподаватели: `id`, `name` |
| GET | `/api/v1/groups/{id}/schedule` | Расписание группы |
| GET | `/api/v1/teachers/{id}/schedule` | Расписание преподавателя |
| GET | `/api/v1/me` | Название токена, права, часовой пояс |
| GET | `/api/v1/classrooms` | Кабинеты: `id`, `name`, `address`, `isHidden` |
| GET | `/api/v1/lessons?from=&to=` | Пары за период до 31 дня с фильтрами |
| GET | `/api/v1/lessons/{id}` | Одна пара |
| POST | `/api/v1/lessons/batch` | Пакет до 500 операций create/update/delete, `dryRun`, `notify` |
| POST | `/api/v1/lessons` | Новая пара |
| PATCH, DELETE | `/api/v1/lessons/{id}` | Изменение или удаление пары |
| POST | `/api/v1/teachers`, `/api/v1/groups` | Новый преподаватель или группа |
| PATCH, DELETE | `/api/v1/teachers/{id}`, `/api/v1/groups/{id}` | Переименование или удаление (`?force=true`) |

Пакет операций атомарный: сначала проверяются все операции, затем они записываются одной транзакцией.
При ошибке проверки ответ 422 с `error.details: [{ index, message }]`, база не меняется.
Применённые изменения пар пишутся в «Отчёты» с названием токена. Уведомления отправляются только при `notify: true`.

Кодируйте ID через `encodeURIComponent` при вставке в URL.
Списки принимают `limit` (1–500, по умолчанию 100) и `offset` (по умолчанию 0).
Ответ: `{ "data": [...], "pagination": { "limit": 100, "offset": 0, "total": 123 } }`.
Сортировка: ID по возрастанию. Для следующей страницы увеличьте offset на limit.

Расписание принимает `weekStart=YYYY-MM-DD`.
Без параметра период начинается в понедельник текущей недели.
С параметром период начинается в указанную дату и длится семь календарных дней.
Начало включено, конец исключён. Часовой пояс: Asia/Yekaterinburg для УРТК, Europe/Moscow для РГСУ.
Ответ содержит `data`, `entity` и `period: { start, end, timezone }`.
`data` — плоский список занятий по времени начала, затем по ID.
Поля занятия: `id`, `title`, `start`, `end`, `index`, `subgroup`, `type`, `meetingUrl`, `teacher`, `group`, `classroom`.
`meetingUrl` — ссылка на видеовстречу, которую добавил подтверждённый преподаватель, либо null.
Связи могут быть null. Даты занятий передаются в ISO 8601 UTC.
Скрытые от студентов занятия исключены для обоих типов расписания.
Отсутствие занятий: HTTP 200 и пустой `data`. Неизвестный ID: HTTP 404.

Пример (TOKEN задайте в своём окружении):

```sh
curl 'https://YOUR_HOST/api/v1/groups?limit=100&offset=0' \
  -H "Authorization: Bearer $TOKEN"
```

## Ошибки и статистика

Формат ошибки: `{ "error": { "code": "UNAUTHORIZED", "message": "..." } }`.
Коды HTTP: 400 — неверные параметры; 401 — отсутствующий, неверный или отозванный токен;
403 — нет права; 404 — неизвестный маршрут или объект; 405 — неподдерживаемый метод;
409 — конфликт; 413 — тело больше 1 МБ; 422 — операции не прошли проверку; 500 — внутренняя ошибка.
Все ответы содержат `Cache-Control: no-store`.

Счётчик увеличивается атомарно после проверки действующего токена, до чтения данных.
Он учитывает запросы всех методов, включая ошибки 400, 403, 404 и ошибки обработки после авторизации.
Неверные токены, неподдерживаемые методы и ошибки базы при самой проверке токена не учитываются.
`lastUsedAt` хранит время последнего принятого запроса. После отзыва статистика сохраняется.
Панель обновляет статистику каждые 15 секунд.

## Применение схемы

В репозитории нет истории Prisma Migrate. Подготовлен отдельный файл `docs/sql/add-api-tokens.sql`.
Он создаёт только таблицу ApiToken и уникальный индекс tokenHash, без изменения существующих строк.
Перед применением подтвердите целевую базу и проверьте отсутствие таблицы ApiToken.
Примените SQL в транзакции после одобрения изменения базы. Затем выполните `prisma generate` и сборку приложения.
Не используйте `db push` для обновления production: оно может применить другие расхождения схемы.

Права токенов добавляет `docs/sql/add-api-token-scopes.sql`: колонка `scopes TEXT[] NOT NULL DEFAULT '{}'`.
Существующие строки получают пустой список и остаются только для чтения. Сделайте дамп перед применением.
